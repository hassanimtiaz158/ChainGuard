# S2: Access Control

- **SWC:** SWC-105 (unprotected withdrawal), SWC-115 (authorization via `tx.origin`)
- **Severity:** high
- **Real-world:** Parity Multisig Wallet (2017)

## The Vulnerability

`VulnerableWallet` has two independent access-control defects.

### 1. Unprotected ownership transfer

```solidity
// VulnerableWallet.setOwner()
function setOwner(address newOwner) external override {
    emit OwnerChanged(owner, newOwner);
    owner = newOwner;                      // no onlyOwner, no msg.sender check
}
```

Anyone can call `setOwner` and make themselves the administrator. Once the
attacker owns the wallet, the owner-gated `sweep` happily hands over every wei.

### 2. Authorization by `tx.origin`

```solidity
// VulnerableWallet.emergencyWithdraw()
if (tx.origin != owner) {                  // tx.origin, not msg.sender
    revert NotOwner();
}
```

`tx.origin` is the account that started the transaction; it stays constant down
the whole call chain. If the owner is lured into calling a malicious contract,
that contract can call `emergencyWithdraw` and the check still passes, because
`tx.origin` is the owner even though `msg.sender` is not.

## The Fix

`SecureWallet` inherits OpenZeppelin `Ownable`:

- Every privileged function (`setOwner`, `sweep`, `emergencyWithdraw`) carries
  `onlyOwner`, and ownership only changes through the owner calling `setOwner`.
- Authorization compares `msg.sender`, never `tx.origin`, so a contract the
  owner calls does not inherit the owner's authority.

An unauthorised call now reverts with `OwnableUnauthorizedAccount(caller)`.

## Why this matters

Access control is the most common source of catastrophic smart-contract losses.
Real incidents are dominated by two shapes: privileged functions with no guard
at all, and guards that check the wrong thing. `tx.origin` is specifically
dangerous because it makes *any* contract the owner ever interacts with a
potential attacker.

## Exploit walkthrough (lab)

1. Three users deposit 10 ETH into the wallet.
2. The attacker calls `setOwner(address(attacker))` — accepted, because the
   function is unguarded.
3. The attacker calls `sweep(attacker)`. The `msg.sender == owner` check passes
   because the attacker *is* the owner.
4. The wallet's balance drops to 0 and the attacker's profit is the full 10 ETH.

The `tx.origin` bug has its own path: the genuine owner calls a malicious dApp,
which calls `emergencyWithdraw` from inside the owner's transaction.

Against `SecureWallet`, the initial `setOwner` reverts with
`OwnableUnauthorizedAccount`, so nothing is ever transferred.
