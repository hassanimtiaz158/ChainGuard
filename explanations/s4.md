# S4: Oracle Manipulation

- **SWC:** SWC-116 (dependency on a manipulable on-chain value)
- **Severity:** critical
- **Real-world:** bZx (2020)

## The Vulnerability

`VulnerableLending` values a borrower's collateral with the AMM's
*instantaneous* spot price:

```solidity
// VulnerableLending.price()
return _amm.getSpotPrice();   // reserve1 / reserve0, this block only
```

`MockAMM.getSpotPrice()` is just `reserve1 * 1e18 / reserve0`. Anyone can move
those reserves with a single `swap`, so the "price" a borrower is measured
against is whatever the attacker makes it moments before the loan is approved.
There is no averaging, no freshness check, and no sanity bound.

## The Attack

1. Deposit a modest amount of collateral.
2. Swap a large stack of the borrow token into the AMM. Buying collateral
   raises `reserve1` and lowers `reserve0`, so the spot price of collateral
   jumps — in the lab, roughly 4x for a swap equal to the reserve.
3. The pool now believes the collateral is worth far more than it is, so its
   50% loan-to-value limit balloons. Borrow against that inflated valuation.
4. Swap the collateral received from step 2 back into borrow tokens, restoring
   the pool price. The manipulation leaves no trace, but the borrower is left
   holding a debt the (now correctly valued) collateral cannot cover: bad debt.

## The Fix

`SecureLending` replaces the spot read with a TWAP plus two guards:

```solidity
// SecureLending.price()
if (_oracle.isStale(MAX_STALENESS)) {
    revert StalePrice();
}

uint256 twap = _oracle.consult(PERIODS);
uint256 spot = _amm.getSpotPrice();
uint256 deviation = spot > twap ? spot - twap : twap - spot;
if (deviation * BPS > twap * MAX_DEVIATION_BPS) {
    revert PriceDeviation(spot, twap);
}
return twap;
```

- **TWAP averaging.** `MockTWAPOracle` records cumulative `price * time`
  checkpoints; `consult(10)` returns the average over the last ten intervals. A
  one-block reserve skew barely moves a ten-interval average, so the honest LTV
  still applies.
- **Deviation guard.** If the current spot somehow departs from the average by
  more than 10%, the read reverts with `PriceDeviation` instead of trusting
  either number.
- **Staleness bound.** A price nobody has refreshed within the last hour is
  rejected with `StalePrice`.

## Why this matters

Reading a price from a single, tradeable pool conflates *the cost to move a
number* with *the truth*. Any protocol that lets a user act on that number in
the same transaction they move it is lending against value that does not exist.
The fix is to price against something expensive to move (a sufficiently wide
TWAP, or a genuine multi-source oracle) and to bound how far the live price may
diverge from it.

## Exploit walkthrough (lab)

Starting state: the AMM holds `1,000 TKA / 1,000 TKB` (price `1.0`); the
attacker holds `100` collateral and `1,000` borrow tokens.

1. The attacker deposits `100` collateral. At the honest price its value is
   `100`, so the honest borrowing limit is `50`.
2. It swaps `1,000` borrow tokens into the AMM. The collateral price rises to
   about `3.99`; the pool now values the same `100` collateral at about `399`
   and raises the limit to about `199`.
3. It borrows `~199` — roughly four times the honest maximum.
4. It swaps the collateral acquired in step 2 back to borrow tokens, recovering
   the skew capital and restoring the price.
5. Net: the attacker keeps a positive profit, and the pool is short by the
   over-borrowed amount.

Against `SecureLending`, step 2 moves the spot far from the ten-interval TWAP,
so the very next price read reverts with `PriceDeviation`. The whole attack
unwinds, no debt is recorded, and the pool's balance is unchanged.

## Tests

| Test | What it pins down |
|---|---|
| `test_exploit_succeeds_on_vulnerable` | Spot price and collateral value inflate; borrow exceeds the honest LTV; attacker profits (logs value before/after) |
| `test_exploit_fails_on_secure` | Reverts with `PriceDeviation`; no debt, no profit, pool untouched |
| `test_secure_borrow_at_true_price_works` | An honest borrower is unaffected by the guards |
| `test_secure_reverts_when_oracle_stale` | An unrefreshed price is refused with `StalePrice` |
| `test_vulnerable_reverts_when_borrow_exceeds_ltv` | Even the vulnerable pool enforces LTV at the honest price |
| `test_vulnerable_honest_round_trip` | Deposit/borrow/repay/withdraw works on the vulnerable pool |
| `test_vulnerable_repay_and_withdraw_guards` | Withdraw-then-unhealthy and overpay paths behave correctly |
| `test_secure_withdraw_collateral_requires_health` | Collateral cannot be withdrawn into an under-collateralised state |
| `test_repay_caps_at_outstanding_debt` | Overpaying only clears the debt |
| `testFuzz_secure_borrow_repay` | Honest round trips at any size leave the pool whole |
| `test_revertWhen_inputsAreInvalid` | Zero amounts and over-withdrawals are rejected |
| `test_revertWhen_attackerHasNoSeed` | The attack cannot start unfunded |
| `test_revertWhen_constructorRejectsZeroTarget` | The attacker rejects a zero target |
| `test_profitIsZeroBeforeAttack` | `profit()` reports zero before any attack |
