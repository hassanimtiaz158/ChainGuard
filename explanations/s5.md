# S5: Flash-Loan Governance Attack

- **SWC:** SWC-105 (unauthorized withdrawal of protocol funds)
- **Severity:** high
- **Real-world:** Beanstalk (2022)

## The Vulnerability

`VulnerableGovernance` measures voting power with the caller's *live* token
balance:

```solidity
// VulnerableGovernance.castVote()
uint256 weight = token.balanceOf(msg.sender);   // whatever the voter holds now
```

Nothing ties that balance to the voter. If voting power can be acquired and
released inside a single transaction, then it can be acquired for free: the
"votes" cost only gas. Flash loans exist precisely to hand out large balances
for one transaction, so the two combine into a governance takeover.

## The Attack

The whole attack is one transaction, executed by `Attacker.onFlashLoan`:

1. `attack()` borrows the lender's entire governance-token liquidity with
   `MockLender.flashLoan`.
2. Inside the callback the attacker now holds millions of tokens, so it calls
   `castVote` and the vulnerable governance counts that full balance as votes.
3. The attacker repays the loan in the same callback, leaving its balance at
   zero and the lender whole.

The proposal now has enough `forVotes` to clear quorum. Once the voting window
closes, `execute` pays the governance treasury to the proposal's beneficiary —
the attacker. The attacker never owned a single token.

## The Fix

`SecureGovernance` fixes the weight to the block the proposal was opened:

```solidity
// SecureGovernance.castVote()
uint256 weight = _token.getPastVotes(msg.sender, p.snapshot);
```

`GovernanceToken` is an OpenZeppelin `ERC20Votes` token, so it keeps a checkpoint
history of each account's voting power. `getPastVotes(account, snapshot)` answers
"how many votes did this account have at the end of block `snapshot`?" — a number
that cannot be changed after the fact. Tokens acquired *after* the snapshot, such
as a flash loan taken out moments before voting, contribute zero. An honest
holder who already had tokens (and delegated them) at the snapshot keeps full
voting power.

## Why this matters

Governance that reads a spot balance is a price oracle with a `setPrice`
function: whoever can move the balance in the voting transaction dictates the
outcome. Snapshotting — committing to a past block before votes are cast —
decouples voting power from anything that can be temporarily borrowed, traded,
or flash-loaned into existence. Production systems often combine this with
time-locks on execution so that a captured vote still has to survive scrutiny.

## Exploit walkthrough (lab)

- The governance treasury holds `5,000,000 CGG`; quorum is `1,000,000`.
- The lender can advance `3,000,000 CGG`.
- The attacker votes on a proposal whose beneficiary is itself.

Against the vulnerable governance the flash-loaned `3,000,000` are counted, the
proposal passes, and `execute` transfers the full `5,000,000` treasury to the
attacker.

Against the secure governance `getPastVotes(attacker, snapshot)` is `0`, because
at the snapshot block the attacker held nothing. `votesFor` stays `0`, the
proposal is `Defeated`, `execute` reverts with `ProposalNotSucceeded`, and the
treasury is untouched.

## Tests

| Test | What it pins down |
|---|---|
| `test_exploit_succeeds_on_vulnerable` | Flash-loaned balance is counted, loan is repaid in-transaction, treasury is drained |
| `test_exploit_fails_on_secure` | The same vote carries zero weight; treasury stays intact |
| `test_secure_accepts_honest_snapshot_votes` | A holder with pre-snapshot, delegated tokens keeps full power |
| `test_vulnerable_accepts_honest_votes` | Honest live-balance voting still works |
| `test_secure_tieIsDefeated` | Quorum-sized for/against tie does not pass |
| `test_secure_proposalLifecycle` | Active → Succeeded → Executed, and no double execution |
| `test_votesAgainstAreCounted` | Against-votes are tallied and can defeat a proposal |
| `test_proposalCountTracksProposals` | Proposal ids increment |
| `test_revertWhen_votingOnUnknownProposal` | Unknown proposals are rejected by vote and by state query |
| `test_revertWhen_votingAfterDeadline` | Votes after the window close are rejected |
| `test_revertWhen_doubleVoting` | A voter cannot vote twice |
| `test_revertWhen_executingBeforeDeadline` | Execution before the window closes is rejected |
| `test_revertWhen_executingTwice` | A proposal can only be executed once |
| `test_revertWhen_proposingZeroBeneficiary` | A zero beneficiary is rejected |
| `test_revertWhen_constructorRejectsZeroToken` | The governances reject a zero token |
| `test_revertWhen_attackerRejectsZeroAddresses` | The attacker rejects zero target/lender |
| `test_revertWhen_flashLoanCallbackFromStranger` | Only the lender may trigger the callback |
| `testFuzz_vulnerableWeightsByLiveBalance` | Weight always equals the live balance on the vulnerable governance |
